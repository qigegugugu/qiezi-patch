Design rationale

四个判断，以及为什么不是另一个做法

1底色不用 #121212 → #1E1E1E 平铺

中灰会把玻璃卡"洗平"——卡面比背景亮不了多少，层级只剩描边在撑。改成近黑基底 #08090C + 右上角一团青色天光，玻璃才有可参照的明暗差；OLED 上还更省电。

天光是 radial-gradient 叠在最底层，不跟随滚动，不会抢内容。

2层级靠"字的档位"而不是靠线

标签 300 灰 #9AA2AE，数值 600 白、字号 +2、tabular-nums；单位再降一档到 11px #5F6773。

三档色差 ≥ 2 级，扫一眼先看到数字、再看清是哪项。原来全部 400/白字挤在一起，等于没有层级。

3强调色只给"正在发生的事"

青 #38E1F2 只出现在：曲线主线、运行中状态、当前间隔值。其余全靠白/灰。

如果每张卡都有青色描边，界面会变成圣诞树。蓝色 #0A84FF 保留给系统级动作（链接、危险确认的反面）。

4快门是唯一的"重物"

88dp 双环：外环 conic-gradient 青色扫光、内盘磨砂玻璃、中心 aperture 图标 30dp 带辉光。左右各一个 44dp 次级按钮，间距 34dp 保证拇指不会误触。

运行中只改两件事：外环转呼吸脉冲（2.4s）、内盘转红。不加旋转动画——那是加载态语言，不是录制态语言。

5Picker 从"弹窗填数字"改成滚轮

底部玻璃 sheet，三列滚轮，中缝 rgba(255,255,255,.06) 高亮带 + 上下 1px 发丝线；选中行 22/600 白，邻行降到 18/400 #5C6270 并缩到 .92。

为什么不用逐行模糊：Android 每帧给 N 个 TextView 做 RenderEffect 会掉帧，用透明度 + 缩放模拟同样的景深错觉，成本接近零。

6关于"真模糊"的现实

Android 没有页面级背景模糊 API（setBackgroundBlurRadius 只对 Dialog/浮层，且 12+）。所以玻璃 = 半透明白渐变 + 1dp 高光顶边 + 22dp 圆角，不做 backdrop-filter。

Web 稿里开了 blur(24px) 只是示意；落地版视觉几乎一致，因为背景本身是渐变而非照片。

Motion

动效只做四件事

a进页

内容整体 translateY(8dp) → 0 + alpha 0 → 1，220ms cubic-bezier(.2,.8,.2,1)；卡片按 40ms 依次错开。不要逐元素弹跳。

b按压

快门 scale .96 120ms；次级按钮面亮度 .06 → .13。不用阴影扩散（深色底上几乎看不见）。

c录制

外环 box-shadow 从 0 扩到 14dp 再消失，2.4s 循环；内盘 180ms 转红。停录立即回到静态。

d数值

数字变化用 text 直接换 + 100ms alpha 闪，不做滚动数字——拍延时时每 10s 抖一次滚动会让人心慌。
